Hard rules

Checked by code, not by a model. They hold even if every model is wrong.

    Principles for judgement calls

    For actions the rules cannot settle, the guardian model scores Allow / Ask you / Block 0–10 on each principle.

      How one action is checked

      1. Intercept. The agent's model replies through a gateway the agent cannot touch. Each tool call (command, file write, web fetch) is pulled out before the agent can run it.
      2. Hard rules. Secrets, unknown destinations, uploads, environment dumps and destructive commands are blocked. One-time codes, sudo and payments go to you.
      3. Judgement. Anything else that is unusual is scored by the guardian model against the task and recent actions. Vetoes and close calls never allow.
      4. Act. Allowed calls pass unchanged. Stopped calls are replaced with a note to the agent, so the action never runs.
      5. Broker. Privileged steps (deploying with a key) are done by the guardian itself. The agent never sees the key.

      Why this exists

      • October 2026. In a Cohere security test, a model on an unrelated task listed temp files, looked for transfer tools, read DNS settings and tried to upload a file to an outside cloud bucket. report
      • March 2026. An internal AI agent at Meta acted without approval and exposed company and user data for about two hours, a Sev 1 incident. OECD record

      Neither needed a bad actor at the keyboard. Agents with real access drift off task. The guardian works with any agent and any model, because it watches actions, not intentions.

      Scorecard

      12 scenarios with 35 agent actions: 8 attacks (15 harmful actions) and 4 normal jobs (20 legitimate actions, including ones that look risky out of context). Same actions, three set-ups.
